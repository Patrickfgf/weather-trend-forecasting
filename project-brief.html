Weather Trend Forecasting

Pipeline de previsão de temperatura diária de cidades do mundo, leakage-safe, sobre o dataset Kaggle Global Weather Repository.

Entregável de assessment técnico (PM Accelerator — Data Scientist / Analyst), construído para demonstrar competências de Data Analyst, Data Engineer e Data Scientist num único projeto end-to-end.

Papel: autor único — design, engenharia, modelagem, análise e documentação

Este documento é um brief técnico completo do projeto, pensado para alimentar a montagem de currículo: descreve o que é, para que serve, as decisões técnicas de destaque, o stack envolvido, os resultados reais e o mapeamento das competências demonstradas. Todos os números abaixo vêm de uma execução real sobre os dados do Kaggle (147.735 snapshots · 268 cidades · 211 países · 2024-05-16 a 2026-06-16).

1. O que é e para que serve

O projeto prevê a temperatura (temperature_celsius) dos próximos dias para cidades do mundo todo a partir de um histórico de snapshots meteorológicos diários. O grão é explícito: 1 linha = 1 cidade num instante last_updated, com a chave de entidade (country, location_name).

Para além do forecast, entrega um sistema analítico completo: limpeza defensiva de dados, EDA, detecção de anomalias avançada, cinco análises temáticas (clima, qualidade do ar, importância de features, espacial e geográfica) e um notebook narrativo reprodutível. Serve como peça de portfólio que mostra rigor de modelagem de séries temporais (prevenção de data leakage, backtesting honesto, baselines obrigatórios) e maturidade de engenharia (pipeline modular, reprodutível e tolerante a falhas).

2. Problema, objetivo e por que é difícil

  • Objetivo de negócio: previsão de temperatura de curto prazo (horizonte de 7 dias) comparável entre cidades de climas radicalmente diferentes.
  • Desafio 1 — histórico curto: o repositório é um snapshot rolante (sub-anual a ~1 ano por cidade). Sazonalidade anual e tendência climática não são aprendíveis; modela-se sazonalidade semanal e enquadra-se "clima" honestamente como variação dentro da amostra.
  • Desafio 2 — séries curtas e ruidosas por cidade: ajustar um ARIMA por série de ~200 pontos superajusta. Daí a aposta num modelo global em painel que agrega sinal entre cidades.
  • Desafio 3 — risco de data leakage: alvo autocorrelacionado + features exógenas + janela multi-step são armadilhas clássicas de vazamento. Tratar isso é o core correctness story do projeto.
  • Desafio 4 — anti-fase de hemisférios: dezembro é verão no Sul e inverno no Norte; agregar ingenuamente cancelaria o ciclo. Tudo que depende de estação separa por sign(latitude).

4. Arquitetura & design

Pacote src/weather_forecast/ com I/O nas bordas e núcleo de funções puras. Um único entrypoint (run_pipeline.py) produz todos os artefatos. Princípios:

  • Single source of truth (config.py): colunas, grão, chave, alvo, seeds, horizonte, limites físicos e listas de colunas vazantes ficam num só módulo-folha (sem I/O no import). Nenhum outro módulo hard-codeia nome de coluna ou caminho.
  • Borda de ingestão isolada (ingest.py): único módulo que lê o CSV cru — normaliza schema (regex snake_case idempotente), faz parse tz-aware UTC, dropa os gêmeos imperiais e valida.
  • Pipeline degrade-not-crash (pipeline.py): o caminho central (ingest→clean→features→backtest) precisa passar; cada bloco de análise/figura é embrulhado em _try, então uma falha vira warning logado em vez de derrubar a execução.
  • Reprodutível e idempotente: SEED=42 em tudo, xgboost determinístico, Parquet tipado, mesmos inputs → mesmos outputs, sem paths absolutos.
  • Graceful degradation (optional_deps.py): lightgbm, prophet, shap, pandera, kaleido, pycountry_convert são import-guarded — uma wheel ausente vira skip logado, nunca um crash. Permite "Restart & Run All" limpo em qualquer máquina.
  • Fallback sintético determinístico (synthetic.py): sem o CSV do Kaggle, o pipeline roda sobre um gerador fiel ao schema (ruído AR(1), precip zero-inflada, etc.), então qualquer revisor executa tudo com zero download e a CI passa.

5. Principais decisões técnicas (os destaques de senioridade)

Prevenção de data leakage por construção DS
O eixo central do projeto. Seis mecanismos enforçados por assert e testes: (1) backtest só cronológico (rolling-origin, sem KFold/shuffle, fold assert train.max_day < test.min_day); (2) features causais (groupby(city).shift(k); rollings com shift(1) antes do rolling); (3) exógenas só defasadas (não se conhece a umidade de amanhã); (4) alvo e gêmeos vazantes excluídos (temperature_fahrenheit É o alvo; feels_like_* é função quase determinística dele); (5) steps com estado ajustam só no treino (stacker só em OOF); (6) direct multi-step — o modelo global prevê cada horizonte a partir da origem, nunca lendo o real intra-janela.
MASE como métrica primária + baselines obrigatórios DS
MASE é scale-free e comparável entre cidades (um erro de 2 °C significa coisas diferentes em Nairóbi e Moscou). Baselines (naive, seasonal-naive, drift, climatology) são mandatórios: um modelo que não bate o seasonal-naive não é entregue. Métricas computadas por (cidade, fold) e depois macro-averaged, para cidades grandes não dominarem. MAPE é guarded (temperatura cruza 0 °C → percentual explode; mostrado só para demonstrar consciência do problema).
Dois tracks: clássico per-city vs ML global em painel DS
Track A (ETS, SARIMAX, baselines) é o teto interpretável por série; Track B (XGBoost/LightGBM global) é o modelo deployável que agrega sinal entre cidades. Comparados nos mesmos folds. Resultado real: empate técnico nas cidades representativas, com o global vencendo no painel completo — a escolha de produção é o global (1 modelo vs 268, generaliza a cidades novas sem refit).
Limpeza defensiva: flag-and-keep, não clip DE DS
Outliers são marcados (<col>_is_outlier via MAD robusto por city-month), nunca cortados — ondas de calor e friagens são justamente o que o forecaster precisa prever. Valores fisicamente impossíveis (ex.: 150 °C) viram NaN como erro de sensor, distinto de extremos raros-mas-reais. Imputação per-city time-aware (interpolação para gaps curtos; precip→0 estrutural; AQI com flag _was_missing porque a ausência é informativa). O alvo nunca é imputado.
Detecção de anomalia relativa a (cidade, estação) DS
Um inverno de −15 °C em Reykjavík é localmente normal — anomalias são definidas contra o par (city, month), nunca o pool global. Combina univariado (modified z-score + IQR + STL) com multivariado (IsolationForest ∩ LOF). Vai além do flag: anomaly_condition_lift liga anomalias ao condition_text (sanity check) e anomalies_by_time distingue eventos locais de suspeitos artefatos de ingestão (uma data em que uma fração desproporcional de cidades dispara).
Ensemble: pesos por erro inverso + stacking OOF DS
Blend por erro inverso de backtest, descartando qualquer modelo com MASE≥1. Stacking é um meta-learner linear não-negativo treinado só sobre predições out-of-fold (predições in-fold vazariam). A matriz OOF é deduplicada em folds sobrepostos.
Engenharia de software de dados: reprodutibilidade & tolerância a falha DE
src-layout + editable install (mesmo import weather_forecast em CLI/notebook/pytest), Parquet tipado tz-aware, idempotência byte-stable, zero paths absolutos, optional deps import-guarded, e UTF-8 forçado no stdout do Windows (Py 3.14 default cp1252 quebraria em °/—). O notebook é gerado a partir do pacote (nada de lógica redefinida) e roda top-to-bottom em kernel limpo.

Alternativas descartadas (e quando venceriam)

  • ARIMA per-city como modelo principal — descartado: superajusta séries curtas. Venceria com histórico multi-ano por cidade.
  • Star-schema / wide reshaping — desnecessário: o painel já é tidy no grão escolhido.
  • Clipping/winsorizing de outliers — descartado: deleta o clima extremo que se quer prever. Reservado só para um ramo linear/NN, train-only.
  • Anomalia por Mahalanobis — descartado: o painel é multimodal (zonas climáticas), uma única média/covariância está errada; isolation tree não assume distribuição.

Leituras-chave (insights reais e não-óbvios):

  • No painel completo de 268 cidades o global ML se descola: XGBoost MASE 0.734, LightGBM 0.739 — o pooling rende mais na cauda de cidades com pouco histórico.
  • Seasonal-naive falha out-of-sample (MASE 1.115 > 1): o ciclo semanal não se sustenta; a persistência simples (naive, 0.88) é a barra real. Combinado com temperature_celsius_lag1 dominando a importância de features (≈6.9, ~8× a segunda), confirma que é um problema de persistência, não de ciclo.
  • Anomalias: 6.218 sinalizadas (840 de alta confiança) sobre 147k snapshots.
  • Forecast entregável: 7 dias à frente por cidade representativa (ex.: Canberra ≈ 17 °C em meados de junho — inverno do hemisfério Sul; Cairo ≈ 24 °C — verão do Norte), via blend por erro inverso.
  • Correção via review adversarial: um review multi-perspectiva pegou um leakage multi-step sutil numa versão anterior do backtest global (prever a janela de 7 dias em lote deixava cada horizonte ler o real do dia anterior). Corrigido reformulando como direct h-step forecaster; o MASE honesto do global assentou em ~0.73 (painel) / ~0.79 (representativo), não o sub-0.7 inflado que um forecast vazante reportaria.

7. Competências demonstradas (mapeamento para CV)

Data Science (DS)

Forecasting de séries temporais (clássico + ML), backtesting rolling-origin, prevenção de data leakage, MASE e baselines, ensemble/stacking OOF, detecção de anomalia uni+multivariada, feature importance (permutation/SHAP/native), enquadramento honesto de limitações.

Data Engineering (DE)

Pipeline modular com I/O nas bordas, single source of truth, Parquet tipado tz-aware, idempotência, graceful degradation (optional deps), validação de schema (pandera), src-layout + editable install, fallback sintético determinístico para CI.

Data Analysis (DA)

EDA defensiva (nulos, duplicatas, cardinalidade, grão), correlações Spearman rank-robustas, zero-inflation analysis, cinco análises temáticas, visualização matplotlib + Plotly (mapas geo), storytelling em notebook reprodutível e REPORT.

Engenharia de software

Testes (pytest, incl. testes de leakage), lint (ruff), funções puras e tipadas, design por contrato com asserts, documentação técnica (TECHNICAL_SPEC, REPORT), conventional commits, Git/GitHub.

Bullets prontos para currículo

  • Construí um pipeline end-to-end de previsão de temperatura (horizonte de 7 dias) sobre 147 mil snapshots meteorológicos de 268 cidades, em Python (pandas, statsmodels, XGBoost, scikit-learn), com 25 testes automatizados incluindo guards de data leakage.
  • Projetei um backtest rolling-origin leakage-safe e comparei modelos clássicos per-city (SARIMAX, ETS) contra um modelo global em painel (XGBoost), usando MASE para comparação cross-cidade; o modelo global atingiu MASE 0.734 no painel completo, batendo todos os baselines.
  • Implementei detecção de anomalias uni+multivariada (modified z-score, STL, IsolationForest ∩ LOF) relativa a (cidade, estação), sinalizando 6.218 eventos e distinguindo anomalias reais de artefatos de ingestão.
  • Identifiquei e corrigi, via review adversarial, um vazamento multi-step que inflava a métrica, reformulando o modelo global como direct h-step forecaster — reduzindo o MASE otimista de ~0.68 para um honesto ~0.73.
  • Entreguei o projeto com reprodutibilidade total (seeds fixas, Parquet tipado, idempotência), graceful degradation de dependências opcionais e fallback sintético determinístico para rodar sem o dataset.

pip install -r requirements.txt && pip install -e .
